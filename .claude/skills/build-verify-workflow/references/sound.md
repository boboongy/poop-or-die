# Sound and music timing

Read this before any sound, mix or music work. (Moved out of SKILL.md on 2026-09-27.)

- **A mix probe must print WHICH sounds start when (`Sfx.played` with the segment time, `tests/probe_flood_sound.gd` "SND" lines), from the FIRST recording** (2026-09-27: 5 recording rounds / 15 runs lowering volumes blind did nothing; the log named each 0 dB peak in one run: three sounds on one frame, a crowd's footsteps in step, a step AT the listener). Things that start together are the usual cause: stagger them. `Sfx` events can set their own `max_db`.
- **Measure the real mix, per channel, several runs, find the source by elimination** (about 40 min, 2026-09-27): `AudioStreamPlayer3D.max_db` defaults to +3 dB, so a 3D sound gets LOUDER than its volume up close (`Sfx.MAX_3D_DB` caps it); a mono downmix hid clipping on one channel (`tools/peaks.py` reads both); a clip 1 run in 3 means one clean run proves nothing; muting one source per run found the cause in one step.
- **Short sound files (< 0.3 s) lose their attack to the engine's fade-in:** check the first 10 ms, pad 30 ms of silence in front (`tests/probe_footsteps_sound.gd`).
- **Adding/removing a bus effect mid-game rebuilds every effect on that bus:** add once, toggle with `set_bus_effect_enabled`.
- **Anything timed to MUSIC must read the audio clock** (`dance.gd song_time()`: `get_playback_position() + get_time_since_last_mix() - get_output_latency()`, unwrapped over loops), including camera moves that must fit a beat. Headless uses the dummy driver: only a WINDOWED probe (`tests/probe_dance_sync.gd`) checks sync.
- Every dialogue change: `python tools/make_voices.py` (run.sh fails a file that prints VOICE MISSING). A voice change to some casts: `--redo=cast1,cast2` (Piper re-rolls every line it renders).
- **A probe's SND log must also name the sounds that are NOT Sfx one-shots** (bubble voices, loops like the bed and the boombox): 2026-09-28, three Level 5 peaks had no logged cause until the bubble voices were logged; the rest was found by muting one source per 3 runs (bed, gibberish, steps). Mute by elimination FIRST, not after lowering volumes.
- **"It fires" and "its peak is >= -12 dB" do not mean the owner HEARS it:** 2026-09-28 Bob's poop blast passed both, but was dull (lowpass 3 kHz) and 3-5 LU quieter than a comparable sound; a windowed recording showed it under a footstep. Judge a must-hear sound by its LOUDNESS (`tools/sound_levels.py --lufs`) against a reference sound the owner did hear, then a windowed probe.
- Measuring a FILE's peak: never `ffmpeg -ac 2` on a mono file (it upmixes 3 dB down: every level read 3 dB quiet); `tools/sound_levels.py` reads the file's own channels. Piper spells an all-caps non-word letter by letter ("OOF!" = "O. O. F.", 2.3 s): write grunts as words ("Ooff!!").
- **New voice or sound files are invisible to headless tests until imported:** after `python tools/make_voices.py` (or any new .ogg/.wav) run `"<console exe>" --headless --path . --import` (2026-09-28: 6 VOICE MISSING right after making them).
